# Чек-лист: безопасная архитектура AI-интенсных сценариев в 5 шагах

Чтобы не потеряться в теории, практический минимальный чек-лист для любых образовательных и личных сценариев:

1) **Слой границ**  
Определите, какие действия AI может выполнять сам, а какие требуют явного подтверждения человека в каждом контексте.

2) **Слой памяти**  
Разграничьте память о фактах, эмоциях и отношениях. Последние должны иметь короткий срок и простой механизм удаления по запросу.

3) **Слой согласия**  
Согласие не одноразовое. Для близости нужны: по каналу (текст/голос/медиа), по времени, по роли участника, по цели.

4) **Слой протокола**  
Все переходы между устройствами и сервисами должны иметь совместимый формат разрешений и доказуемый журнал решений.

5) **Слой выхода**  
Любая цепочка должна поддерживать ручной выход пользователя: остановить, пересмотреть, отложить, переопределить.

Минимум для “нормально”:
- прозрачный статус доступа;
- объяснимость, почему агент что-то рекомендовал;
- обратимость действий;
- сохранение приватности по умолчанию.

**Локальный акцент.** Прямой контроль ядра на устройстве/в доверенном контуре снижает риски утечки и упрощает диалог с регуляторами, но сам по себе не решает задачу. Нужны совместимые интерфейсы и внешние аудит-каналы.

**Интернациональный акцент.** Если проект движется в сторону глобальных сценариев, нужен нейтральный слой языка правил, иначе одна юрисдикция станет узким местом.

Идея не “новой магии”, а дисциплины: чем раньше встраивается, тем меньше конфликтов потом — с законом, с партнёром, с самим собой.
